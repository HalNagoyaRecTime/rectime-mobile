# 開催状況と次の集合（iOS）

## 責務

- #316：iOSの表示コンポーネント、表示用DTO、容量制限、外観、OSのカウントダウン。Androidのライブ専用通知・専用取得は廃止する。
- #379：通常通知の取得順。通常のFCM受信・通知表示・権限・トークンは維持する。
- #380：共通の日付解釈、対象イベントの補完、優先順位、本人予定の選択、開始・終了・期限。

## データと更新

既存のLocalCache/EventScheduleStoreから一覧・本人参加・詳細を共有する。独自APIや永続キャッシュは追加しない。開催日はAPIのevent_date（JST）を使い、ラウンド開始時刻を集合時刻から推測しない。日跨ぎの終了時刻は既存のスケジュールと同じく対象外。

最初のイベントの1時間前から表示対象とする。前面で2時間先までと本人参加イベントを補完し、最大3件並列で取得する。詳細画面と通信を共有し、前面復帰・一覧更新・時間窓へ入った予定で取得する。前面の時刻確認は30秒ごと。終了後10分を過ぎた詳細は補完しない。

タイムアウトや一時障害では保存済み情報と実際の取得日時を維持する。キャッシュから現在時刻で表示を再計算するが、失敗によって取得成功と扱ったり表示期限を延長したりしない。403/404の失効や認証世代の変更は既存Storeに従う。

## 選択と期限

本人の集合は、集合時刻を迎えて開始予定まで保持されているものを先に選び、その後に最も早い未来の集合を選ぶ。開始時刻がない、または集合以前の場合はイベント終了まで保持する。並行ラウンドの終了を推定しない。

主イベントは開催中の候補から「下段の本人予定と同じイベント→本人が参加するイベント→開始時刻が新しいイベント→イベントID」の順で選ぶ。本人のイベントが開催前なら、それを理由に開催中の別イベントを隠さない。開催中がなく終了後10分以内のイベントがあれば、それを次のイベントより先に残す。

表示中のイベント終了・本人予定の開始などの案内可能な区切りから10分後を表示期限にする。staleDateで期限切れとなったら内容を消し「最新の情報を表示するにはRE:CREATIONを開いてください」を中央に表示する。最新のイベントの終了後10分からは終了案内とお礼を表示し、終了から約1時間の固定期限でOSへ終了・削除を指定する。

## 見た目

全体160pt（上段84pt・下段76pt）。タイトル15pt、開催時間13pt、集合時刻22pt。下段は原色オレンジ、上側だけ22ptの角丸。場所とブランドは11pt。横幅に収まらなければブランドを外し、それでも長ければ場所を省略する。

上段はタイトル・状態、時間・会場、バー、全ラウンド数・確認案内。次のラウンド時刻は表示しない。下段は本人イベント名・残件数・状態、集合時刻・残り時間、ラウンド・会場・集合場所。「会場：」「集合：」は付けない。

バーはアプリの青、本人の丸はオレンジ。iOSへ最大24件の実ラウンドを渡し、幅から丸の数を決め、省略波線は最大2か所。終盤は過去側で枠を埋める。開始時刻のない丸は時間軸に配置せず、イベント全体のバーを表示する。

残り時間はiOS 18以降の標準TimeDataSourceとSystemFormatStyle.Timerで、一単位の時間・分を日本語表示して0で止める。iOS 17では時計形式へフォールバックする。独自タイマー・独自FormatStyleは追加しない。

配色は本体が読み取るシステム外観をActivityKitへ渡す。ウィジェットが壁紙由来の外観を渡すOSを補い、前面復帰・外観変更時に更新する。本体停止中の外観変更が即時反映されることは保証しない。Dynamic Islandと常時表示の減光中は暗い配色にする。

JSONは3,500バイトを目安に副表示・丸を減らし、Swift側で属性込み4KBを確認する。

## OSの制約と確認

ロック中に自動で進むのは標準のバーとカウントダウン。丸の着色・状態タグ・表示対象の選び直しは再描画時点の値であり、この制限は許容する。中央の更新案内にはOSの期限切れ通知を使う。お礼への切り替えはアプリから状態を更新できた場合に行い、アプリ停止中は期限切れの更新案内になる。APNsのライブ更新や常駐処理は追加しない。ユーザーが閉じたActivityは同日起動中に自動復活させない。

今回はビルド・テストを実施しない。実機でiPhoneの外観、一単位のカウントダウン、狭幅、長い場所、同時開催、集合前後、終了後の猶予、通信失敗、ログアウトを確認する。
