# iOSライブアクティビティ（初期実装）

PR #313（アプリ名統一）の後ろに実装する。本人の出場情報は #309 の実装を利用する。Androidは今回対象外。

## 表示と取得

- スケジュールの既存ViewModelから予定と本人の出場判定を渡す。専用のHTTP取得・別キャッシュは作らない。
- 開催中の競技名、会場、開始～終了の進行バーを表示する。
- 上段は本人が出場中ならその競技、そうでなければ次の本人の出場予定を表示する。本人の予定がなければ上段は表示しない。
- 下段は開催中のイベント1件を表示する。未開催なら当日の次のイベントを表示し、開始前もバーと開始～終了時刻を残す。終了した競技は次の候補へ切り替え、当日の残りがなければ終了表示にする。
- ラウンドありは番号付きの丸を重ねた太いバーと現在ラウンド、ラウンドなしは時間経過のバーを表示する。上段には取得できた場合のみ自分の出場ラウンド番号を表示する。同じ競技が上下に来た場合、下段の名前は「競技全体」にする。
- 集合前は集合まで、集合後の開始前は開始まで、開催中は終了までをOSのタイマー表示でカウントダウンする。
- 前面表示中は15秒間隔で選択を更新する。通信は増えない。
- ログアウト・アカウント切り替え時は終了。ユーザーが閉じたActivityは同日起動中に自動で再作成しない。

## 開催日

- 現APIには開催日の契約がないため、日付をハードコードしない。
- Debugは当日の日本時間に既存の時間割を当てはめ、毎日表示できる。
- Releaseは開催日が未取得なら表示しない。
- 将来APIが返す開催日を共有スケジュールの`eventDate`へ渡す。形式は日本時間の`YYYY-MM-DD`を想定するが、API契約確定後に接続する。現在はnullを渡す。

## バックグラウンドの制約と次のAPI改修

ActivityKitのバー・カウントダウンはOSが更新するが、アプリ停止中に次の競技を選び直すことはできない。
切り替えが必要な最初の時刻（開催中の終了、次の競技開始、日付変更）を`staleDate`にし、以降は「更新待ち」を表示する。保存済みの競技情報・時間帯・バーは消さない。
完全なバックグラウンド更新にはActivityKit専用のpush token登録とAPIからの更新・終了通知が必要。現在のFCM通知だけでは代用できない。
ライブアクティビティ自体にもOSによる最大8時間の制限がある。

## 実機での確認

XcodeのiosAppスキームをDebugで実機起動し、ログインしてスケジュールを取得した後にロックする。
iOS設定でライブアクティビティが許可されている必要がある。
ロック画面、Dynamic Island、出場予定なし、同時開催、境界時刻、ログアウトを確認する。
コード署名を無効にしたビルドは実機へのインストール・表示確認ではない。

## デザイン試作

`rectime_live_activity_prototype.html`を参考に、オレンジ・水色・黄色の配色と上下2段の情報構成を試作している。最終デザインではない。
ロック画面の背景・文字色はComposeのアプリテーマから渡す。テーマ変更時も既存Activityを更新する。現在のアプリテーマは2種類ともライト配色で、ダーク配色はまだ未実装。Dynamic IslandはOSの黒い背景に合わせる。
HTMLの大きなカードをそのまま移植せず、ロック画面の高さ制約に合わせたコンパクトな表示にしている。
実APIの集合時刻・集合場所・ラウンド情報は現在の共有スケジュールには渡されていない。Debugの実機サンプルではこれらを表示できるようにしている。
`RecreationLiveActivity.swift`のXcodeプレビューで、ライト・ダーク・出場中・更新待ちを比較できる。プレビュー用データはAPIやアプリのスケジュールには保存しない。

### DBを変更しない確認方法

Xcodeで`RecreationLiveActivity.swift`を開き、Canvasを表示する。
「ロック画面・状態切り替え」では出場予定・ダーク配色・全競技終了のContentStateを切り替えられる。
「Dynamic Island」では拡大表示を確認できる。通常のViewプレビューでは出場中・同時開催・更新待ちも比較できる。
ダークのサンプルは将来の配色確認用であり、アプリに新しいテーマモードを追加するものではない。
これらはDebugのプレビューだけで動作し、DB・キャッシュ・本番Activityに架空の予定を保存しない。
実機でアプリ停止中の切り替わりを確認する場合は別途Debug専用の短い予定が必要。Canvasでの表示確認とは分けて扱う。

左上の画像は、本体と同じ`AppIcon.icon`をWidget拡張でもコンパイルして読み込む。別のロゴやアイコン画像は作成しない。

### 実機用の現在時刻サンプル

iosAppスキームのRun環境変数`RECREATION_LIVE_ACTIVITY_DEMO=1`を有効にしている（Debug限定）。
ログイン後に予定の復元が終わると、ウィジェットにだけ現在時刻基準の架空の予定を渡す。
起動直後は出場予定、30秒後は呼び出し中、2分後は開催中、12分後に自分の競技が終了する。
このサンプルは表示遷移を短時間で比較するため集合から開始までを90秒に圧縮している。
アプリを終了して起動し直すと時刻をリセットする。通常表示へ戻すにはRun環境変数を無効にする。
DBや共有のスケジュール・キャッシュは変更しない。ログアウトでは通常と同じく終了する。

ラウンドの試作は集合時刻＋15分を暫定の開始として、開始予定を過ぎたラウンドを全ラウンド数に対して表示する。
同じラウンドの集合が複数あっても総数は重複させない。時刻未定や集合情報なしでは表示しない。
これは予定に基づく目安であり、試合の遅延・延長・中止を反映する実進行ではない。
実データを使うにはイベント詳細で取得している集合一覧を共有スケジュールへ連携する必要がある。

アプリ前面表示中の状態確認は15秒間隔。ロック後はOSのタイマー・進行バーだけが継続し、
集合／開始の境界で最新状態を保証するにはAPIからのActivityKit更新通知が必要。
現段階は境界後に更新待ち表示にするので、状態を切り替えて確認する際はアプリを一度前面へ戻す。
区切り線・一覧・件数見出しを削除し、下段はイベント名と一本のバーだけにする。サンプルでは上段の自分の第3ラウンドと下段の同じイベントの全5ラウンドを照合できる。
