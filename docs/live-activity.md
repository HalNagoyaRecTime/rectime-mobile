# 開催状況と次の集合（iOS）

## 責務

- #316：iOSのロック画面・Dynamic Island、表示用DTO、容量制限、外観、OSの時間表示。
- #379：通常通知の取得順。
- #380：日付の共通解釈、補完取得の範囲、イベントと本人予定の選択、開始・終了・表示期限。

Androidのライブ用通知投稿・専用の購読・定期取得は削除する。Androidはプラットフォーム判定でライブ処理を開始しない。通常のFCM受信・通知表示・チャンネル・権限・トークンは変更しない。

## データと表示

一覧・本人参加・詳細は既存のLocalCache/EventScheduleStoreを共有する。独自APIや永続キャッシュは追加しない。開催日はAPIのevent_date（JST）を使い、ラウンド開始時刻を集合時刻から推測しない。

全体160pt（上段84pt・下段76pt）。上下のタイトルは15pt、開催時間13pt、集合時刻22pt。本人カードは原色オレンジ、上側だけ22ptの角丸。場所とブランドは11pt。収まらなければブランドを外し、次に場所の末尾を省略する。

上段は主イベント名・状態、開催時間・会場、バー、全ラウンド数・確認案内。「次のラウンド」の時刻は表示しない。下段は本人イベント名・残件数・状態、集合時刻・残り時間、ラウンド・会場・集合場所。「会場：」「集合：」は付けない。

バーはアプリの青、本人の丸はオレンジ。最大24件の実ラウンドを渡し、幅から表示数を決め、省略波線は最大2か所。終盤は過去側で枠を埋める。開始時刻が不明の丸は時間軸に配置せず、イベント全体のバーを表示する。

残り時間はiOS 18以降の標準TimeDataSourceとSystemFormatStyle.Timerで、一単位の時間・分を日本語表示し、0で止める。iOS 17では時計形式へフォールバックする。独自FormatStyle・独自タイマーは作らない。

配色は本体が取得したシステム外観をActivityKitへ渡し、iPhoneのロック画面が壁紙由来の外観を渡すOSを補う。前面復帰・外観変更時に反映するが、本体停止中の設定変更が即時反映されることは保証しない。Dynamic Islandと常時表示の減光中は暗い配色にする。

JSONは3,500バイトを目安に副表示・丸を絞り、Swift側で属性込み4KBを確認する。通常の注意書きは「最新の予定はアプリでご確認ください」。案内できる期限をstaleDateへ渡し、期限後は「最新の情報を表示するにはRE:CREATIONを開いてください」を中央に表示する。

## 更新と後続

前面で詳細を最大3件並列補完し、詳細画面と通信を共有する。前面だけ30秒ごとに時刻を確認する。一時障害・タイムアウト時は保存情報と取得日時を維持して表示を再計算する。403/404の失効・認証世代の変更は既存Storeに従う。

#380で最初のイベントの1時間前からの開始、イベント終了後10分の猶予、完全終了後約1時間の保持、本人集合の開始予定までの保持、同時開催の優先順位を実装する。

ロック中に自動で進むのはOSのバーとカウントダウン。丸の着色・イベント選択・状態タグは再描画時点の値であり、この制限は許容する。APNsによるライブ更新・常駐処理は追加しない。ユーザーが閉じたActivityは同日起動中に自動復活させない。

## 確認

今回はビルド・テストを実施しない。実機でiPhoneの外観、一単位のカウントダウン、狭幅、長い場所、同時開催、集合前後、通信失敗、ログアウトを確認する。
