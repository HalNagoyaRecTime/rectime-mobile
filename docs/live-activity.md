# 本人予定のライブアクティビティ（iOS）

## PRの責務

- #316：本人予定の表示・DTO・タップ導線・保存値の復元。時刻を持たない表示契約へ置き換える。
- #379：通常通知の取得順。本人予定への切替によって通常FCM通知を変更しない。
- #380：開催日の共通解釈、終了済みイベントと本人ラウンドの選択、残りイベント数。
- #382：共有Storeの鮮度判断と前面復帰時の取得。本人予定以外の詳細補完を行わない。

## 表示と更新

オレンジの160ptカードに本人予定を一件表示する。左上は「自分の予定 / あとNイベント」、中央はイベント名・対象ラウンド・会場・集合場所。下段の「時間を確認するにはタップ」とアプリ名・アイコンを同じベースラインに揃える。幅が不足すればブランドを外す。件数で高さ・レイアウトを変えない。

カードをタップすると対象イベント詳細を開く。通常通知の受信イベントは流用しない。Androidのライブ表示は提供せず、通常FCM受信・表示・権限・チャンネル・トークンを維持する。

既存Storeの `/me/events` と本人参加イベントの `/events/{id}` を共有し、本人集合IDのみを取り出す。イベント詳細にはタイトル・会場・集合場所が含まれる。廃止予定の旧集合APIは再導入しない。

起動時に保存済み本人予定を復元し、前面復帰で更新する。定期ポーリング・進捗バー・カウントダウン・開催状況・期限切れ案内・お礼は廃止する。staleDateと終了予約は設定しない。一時障害では保存値を使い、復元が不完全なら既存Activityを維持する。参加取り消し・403/404・ログアウトでは旧情報を保持しない。

開催日を含む残り予定の判断を#380で適用する。既存スケジュールの保存済み開催日をJSTで解釈し、前面更新時に終了済みイベントを除く。本人ラウンドは次ラウンド開始まで、最後はイベント終了まで保持する。同じイベント・集合場所の残り本人ラウンドをまとめ、イベントIDの重複を除いて表示中を含む件数を数える。日付未取得・不正なら開催日を推測せず本人予定を残す。取得鮮度の統一は#382で適用する。通常の全体スケジュールの表示ロジックとは分離する。

送信前に属性込み4KB未満を確認する。旧Activityの状態に存在しない新フィールドはSwiftでOptionalとして読み込む。

OS自体の継続時間制限は残る。Apple仕様ではアクティブ表示は最大8時間、その後ロック画面は最大4時間。OSが終了した場合は次の前面復帰で再作成し、ユーザーが閉じたActivityは同じ起動中に自動再作成しない。

参照: https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities

ユーザー指定によりビルド・テストは実行しない。既存テスト・ネイティブDTO用フィクスチャは新契約へ追従する。最新表示とディープリンクは実機確認待ち。
