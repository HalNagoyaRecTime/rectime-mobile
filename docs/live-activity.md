# 開催状況と次の集合

PR #333（#370取り込み済み）の共有キャッシュを使う。表示の統一は#358・#359、画像は#372の後ろに置く。

## 共通データと取得

- 一覧・本人参加・イベント詳細は既存のLocalCache/EventScheduleStoreを共有する。専用のAPI・保存領域は作らない。
- 一覧APIの`event_date`（JSTのYYYY-MM-DD）を使う。未設定・不正・対象日時外は表示しない。Debugでも今日へ読み替えない。
- ログイン中・アプリ前面で、開催中か2時間先までに始まるイベントの詳細を補完する。同時取得は3件までで、詳細画面と同じ要求を共有する。
- 一覧の更新、前面復帰、時間窓へ新しく入ったイベントで詳細を取得する。30秒の確認は前面だけで動き、時間窓が同じなら通信を増やさない。
- バックグラウンドでは補完処理を中止する。他画面が待つ共有通信は巻き込まない。
- 詳細の更新を購読し、取得が失敗しても保存済み表示を維持する。403/404は共有Storeで失効、401だけではキャッシュを消さない。認証の失効判断は既存AuthViewModelに任せる。

## 表示

- 上段は時間割上の開催状況、下段は本人の次の集合。iOSは主イベント1件、Androidは取得した最大3件を標準通知で表示する。
- 集合番号、集合時刻、場所、ラウンドの開始予定はAPIの実値だけを使う。集合からの推定、呼出、集合済み・実際の開催中という断定はしない。
- 複数の集合は時刻→番号順で次の1件を選ぶ。過去の集合は開始予定を過ぎたら除外する。親ラウンド開始後でも未来の集合は保持する。開始未設定はイベント終了まで保持し、時刻や本人情報がない集合は作らない。
- ラウンドには終了時刻がないため、開始予定を過ぎたかどうかだけを表示する。並行ラウンドの終了を推定しない。
- iOSは確定したHTML案に合わせ、全体160pt、上段80pt・下段80ptで表示する。上下のタイトルは15pt。下段は原色オレンジ、上側2か所だけ22ptの角丸。集合時刻は22ptで、タイトルと場所の間の中央に置き、残り時間は右へそろえる。
- 上段はタイトル・状態、実施時間・全ラウンド数・会場、番号付きバー、次の開始予定・確認案内。開始予定を持つラウンドがない場合、次の開始予定は空欄にする。最後のラウンドの開始後も最後の時刻を残す。下段は本人イベント名・残件数・状態、集合時刻・残り時間、ラウンド・実施場所・集合場所。「会場：」「集合：」は付けない。場所とブランドは11ptでそろえ、実際の横幅で収まらなければブランドを外し、それでも長ければ場所の末尾を省略する。内部の集合番号はiOSの通常表示に出さない。
- ロック画面の配色はWidgetKitが渡すSwiftUIの`colorScheme`から決める。背景はライトで白、ダークで暗いグレー。UIKitの別のtraitで背景色を解決したり、受け取った外観を再設定したりしない。終了・更新案内の外側背景も同じ判定を使う。Dynamic Islandは黒背景、本人カードは両外観でオレンジを維持する。アプリのライト固定テーマやAPIの取得データに外観を保存しない。
- Androidの既存マーカー7件は維持する。iOS用に最大24件の実ラウンド情報を追加し、幅から表示数を決める。開始予定を過ぎた丸を水色、本人を常時オレンジにする。現在付近・本人・最後を優先し、省略は最大2か所。終盤は過去側で表示枠を埋める。開始時刻不明の丸の位置は推測せず、全体の時間バーを表示する。
- iOSの進行バーは通常線・省略波線ともアプリの青に統一する。本人のオレンジは丸だけに使い、バーのグラデーション処理は持たない。
- iOSへ送るJSONは3,500バイトを目安に副表示・丸を減らし、属性を含む4KBをSwift側でも確認する。通常区間のバーと集合までの時間はOSの時間表示を使う。省略波線の塗り・丸の着色・表示対象の選び直しは状態の再描画時に更新される。停止中の任意タイミングでの再描画を保証する独自タイマーは追加しない。
- 通常表示の案内は「最新の予定はアプリでご確認ください」。15分の取得鮮度だけで内容を消さず、iOSのstaleDateには表示中のイベント終了・本人ラウンド開始予定などの案内可能な区切りを使う。その期限後は内容を消し「最新の情報を表示するにはRE:CREATIONを開いてください」を中央に表示する。
- 本人集合の実施場所・イベント終了、残件数・本人予定の取得状況を共通状態から受け取る。本人イベントすべての詳細が揃うまで残件数や「予定なし」を断定しない。集合時刻を過ぎた文言は「集合時間です」。終了画面のデザインも用意するが、実際の終了判定・保持時間は後続PRの共通ロジックで接続する。

## 後続PRとの分担

- #316はiOSの表示コンポーネントと表示に必要な共通データを担当する。既存のStore、認証世代、取得競合・失効対策は維持する。JSの模擬時刻やサンプル値はアプリへ入れない。
- #379の通知取得順管理には触れない。
- #380で開催日の判定、最初の予定の1時間前からの開始、完全終了後約1時間の保持、集合から次の本人予定への選択、取得範囲・情報不足の判断を整理する。`displayMode`の`finished`・`refresh`を共通状態へ接続する。現在の2時間窓や実際の終了時刻を、このデザインPRだけで変更しない。

## OSの制限

- iOSはActivityKit/WidgetKitを使用する。ロック画面とDynamic Islandを表示し、本体のAppIconを使う。復元中に既存Activityを消さず、ログアウト・アカウント切替・対象なしで終了する。
- iOSは最大8時間。既存ActivityのOSによる終了が確認できた場合は、前面で作り直せる。ユーザーが閉じたものは同日起動中に自動で復活させない。
- アプリ停止中はOSの時刻・進行バーだけが動く。次のイベントを選び直すにはアプリを開く必要がある。ActivityKit用APNs更新は今回追加しない。
- Androidは静かなBigText通知を使い、既存の通知許可に従う。通知タップでアプリを開き、2時間で期限切れとする。権限拒否は本体を妨げない。
- AndroidのPromoted Live Updatesは今後のカレンダー予定に適さないため要求しない。foreground serviceやバックグラウンド常駐通信も追加しない。端末によって通知内の表示量は異なる。
- 日跨ぎのイベント（終了<=開始）は既存スケジュールと同じく対象外。開催日APIのない旧キャッシュから日付を推測しない。

仕様の出典: [ActivityKitの制約](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)、[Android Live Updatesの用途と要件](https://developer.android.com/develop/ui/views/notifications/live-update)。
