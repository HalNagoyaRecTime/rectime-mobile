# 通知詳細・イベント説明のMarkdown

本文の保存形式は文字列ひとつです。通知詳細とイベント説明は装飾の有無を判定せず、共通のAppMarkdownで表示します。普通の文章もそのまま入力できます。

- 単独改行は段落内の空白として扱います。
- 行末の空白2個以上＋改行、またはバックスラッシュ＋改行で強制改行します。
- 空行で段落を区切ります。
- 字下げ、行末空白、先頭・末尾の改行をAPIと管理画面で削りません。
- 見出し・リスト・表・コード・HTTP(S)画像を使えます。画像の共通キャッシュと拡大ビューアは従来どおりです。

APIで削られた過去の空白は自動復元できません。APIの空白保持対応をマージ・反映してから、この表示仕様を使います。format列・バージョン分岐・旧形式判定は追加しません。

## 共通の画像キャッシュ

Markdown、画像ビューアー、今後の集合場所・開催場所画像は、共通のCoil ImageLoaderを使う。
URL全体（クエリも含む）を画像の識別子とし、取得成功・304再確認から12時間は再通信しない。
メモリに残った画像も期限を確認する。期限後はETag/Last-Modifiedがあれば条件付き取得、なければ通常取得を行う。
期限内は同じURLで差し替えた画像が即時反映されない。アプリを再起動しても取得時刻はディスクに残る。
通信失敗時は保存済み画像を表示し、失敗を新しい取得成功として扱わない。
Cache-Control: no-storeは保存しない。プロフィール写真は別の既存取得・本人切替方針を維持する。
ディスク容量は従来の上限を維持し、OSのキャッシュ削除・容量不足では12時間以内でも再取得し得る。
