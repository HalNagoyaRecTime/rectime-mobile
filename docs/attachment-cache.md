# 添付ファイルの取得・表示

画像とPDFはURL全体（署名・クエリを含む）をキーに、共通の添付キャッシュで取得する。Coilは保存済み画像の描画に使い、本体を重複してディスク保存しない。プロフィール写真は既存の専用管理を維持する。

- 一覧APIや本文の取得だけでは、画像・PDFを取得しない。
- Markdown画像は表示領域とその前後160pxに入ったときに取得する。PDFリンク（大文字小文字を問わない.pdf、クエリ可）はタップ時に取得する。拡張子のない通常リンクは従来どおり外部リンクとして開く。
- 画像構文のURLは拡張子を要求しない。取得した本体の表示可否は画像デコーダーが判定する。
- 12時間以内は通常再取得せず、それ以降は次の利用時にETag / Last-Modifiedがあれば条件付き取得する。304でも期限を更新する。期限経過による削除はしない。取得失敗時は保存済み本体を再利用する。明示的な再読み込みは期限内でも条件付きヘッダーを使わず再取得する。
- 本体と索引をディスク保存し再起動後も利用する。上限256MiB、最後の利用から30日を過ぎたファイル、容量を超えた場合の利用日時が古いファイルを利用時に整理する。表示中・共有取得中は削除せず、保持終了後に再整理する。
- 単一ファイルが256MiBを超える場合は取得を中止する。no-storeは表示中だけ一時保持し、表示終了後に削除する。
- 同じURLの取得を共有する。画面を閉じるとその利用者の待機を解除し、最後の利用者がいなくなれば通信をキャンセルする。途中ファイルは削除する。
- ログアウト・ログイン切り替えのLocalCache.clearAllで添付キャッシュ、旧画像キャッシュ、共有用一時ファイルと画像メモリを消去する。セッション世代で旧取得の書き戻しを防ぐ。ユーザーがアプリ外に保存したコピーは対象外。

## PDF

添付ビューアは取得中・表示・フォールバック・取得失敗の状態を持つ。進捗の分母が不明なら不定の読み込み表示とし、画面を閉じて取得をキャンセルできる。

iOSはPDFKitで読み込み可否を確認しQuick Lookで表示する。AndroidはAPI 21からの標準PdfRendererを使い、表示付近のページのみ描画する（アプリの対応下限はAPI 26）。デスクトップはOSで開くフォールバックを使う。

表示不能・暗号化等の場合は「ファイルを開く」「ダウンロード」を提供し、OSの対応アプリ・保存先選択へ渡す。Androidに対応アプリがない場合も保存操作を残す。これらの操作は保存済み本体を使い、再取得しない。

## R2の現在の契約

API #530の署名は日本時間の0時を基準に7日有効。同日内は同じキーに同じURLを返す。新しい署名URLを受け取った場合は別キーとして再取得を許容する。署名パラメーターを削ってキャッシュを共有しない。

API #529は実施場所・集合場所のJPEG / PNG / WebP（5MiB以下）に限る。今回のPDF表示はMarkdownのPDFリンクを対象とし、場所画像アップローダーのPDF対応やAPI変更は含めない。
